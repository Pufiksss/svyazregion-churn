# Вопросы заказчику и допущения

Ответственный: **Захар**. Статус вопросов обновляется после ответа заказчика.

| № | Вопрос | Зачем | Текущее допущение |
|---|---|---|---|
| В1 | Считается ли оттоком только расторжение договора или также «тихий уход» (нет трафика, нет оплат, договор не расторгнут)? | Определяет целевую переменную | Только `termination` в журнале событий |
| В2 | Как часто запускается кампания и сколько времени нужно, чтобы связаться с абонентом? | Горизонт и дата расчёта | Ежемесячно, расчёт 1-го числа, горизонт — календарный месяц |

| В4 | Лимит 10 % считается от всей активной базы или от базы после исключений (сегменты, новые абоненты, должники)? | Размер списка | От всей активной базы на t |

| В6 | Можно ли включать в кампанию абонентов с долгом или их ведёт отдел взыскания? | Пересечение процессов | Включаем |
| В7 | Что ценнее: удержать Premium-абонента или любого? Есть ли оценка выручки на абонента? | Взвешивание метрики | Все абоненты равноценны, Recall@10 % |

| В9 | Расторжение по инициативе оператора (за долг) — тоже отток, который нужно предотвращать? Есть ли поле причины? | Чистота целевой переменной | Все расторжения — отток, причина неизвестна |
| В10 | Сохраняется ли история тарифа / скидок отдельно, или только в биллинге? | Признаки | Только биллинг |

## Что нужно из источника «обращения в поддержку»

| Поле | Назначение |
|---|---|
| `ticket_id` | уникальный ключ, проверка дублей |
| `customer_id` | связь с абонентом |
| `created_at` (дата и время, часовой пояс) | отбор обращений до t |
| `available_at` / дата загрузки в хранилище | защита от утечки, если выгрузка запаздывает |
| `closed_at`, `status` | длительность решения, нерешённые обращения |
| `category` / тема (качество связи, биллинг, тариф, перенос номера, расторжение) | признаки по темам; категорию «расторжение» не использовать как признак без проверки |
| `channel` (звонок, чат, офис) | признак |
| `resolution`, `is_repeat` | повторные и нерешённые обращения |
| `csat` / оценка | удовлетворённость |

Единица наблюдения ожидается «одно обращение»; к паре (абонент, t) агрегируем: число обращений за 1/3 месяца, доля нерешённых, дни с последнего обращения.

## Принятые допущения

1. Данные синтетические, масштаб уменьшен; все расчёты — на фактической базе (≈1900–1970 активных абонентов на срез).
2. Время всех дат — московское; событие действует с 00:00 даты.
3. Один договор на абонента, повторных подключений нет (словарь данных, подтверждено журналом).
4. Отсутствие расторжения до 01.10.2026 = «не ушёл в наблюдаемый период», а не «не уйдёт никогда».
5. `billing_preview.csv` — подмножество основного биллинга, не используется.
6. Полные дубли строк биллинга (150) — технические повторы выгрузки, удаляются на этапе 2.
7. Пропуск `traffic_gb` ≠ 0: сохраняется как пропуск с флагом (нулевых значений в данных нет).
8. Пропуск `closing_debt_rub` восстанавливается по тождеству `opening + charged − paid`, которое выполняется на всех полных строках.
9. Отрицательные `voice_minutes` (80 строк) — ошибка источника, заменяются на пропуск.
